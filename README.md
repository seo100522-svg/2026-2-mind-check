# 마음체크인 — 마음체크리스트

> **마음체크인**은 대학생이 자신의 최근 정서와 스트레스 상태를 가볍게 돌아보고, 필요할 때 교내 지원 자원으로 연결될 수 있도록 설계한 다국어 마음건강 지원 프로그램용 웹 애플리케이션입니다.

이 저장소는 공개 설문 흐름, 결과 안내, 말랑이 추천, 운영자 대시보드 및 원자료 내보내기 기능을 함께 제공합니다. CES-D와 PSS-10 결과는 **의학적 진단이나 치료 판단을 위한 것이 아니라 자기점검과 지원 안내를 위한 참고 정보**로만 제시됩니다. 즉각적인 위험이 있거나 긴급한 도움이 필요한 경우에는 앱의 안내와 별개로 **자살예방 상담전화 109**, **112** 또는 **119**에 연락해야 합니다.[3]

| 구분 | 내용 |
| --- | --- |
| 주 이용자 | 대학생 및 프로그램 운영자 |
| 지원 언어 | 한국어, English, 日本語 |
| 자기점검 도구 | CES-D 20문항, PSS-10 10문항 |
| 운영 기능 | 권한 기반 관리자 대시보드, 학과별 집계, 상담 동의자 목록, XLSX 원자료 내보내기 |
| 기술 구성 | React 19, TypeScript, Vite, Express 4, tRPC 11, Drizzle ORM, MySQL/TiDB |

## 주요 기능

### 참여자용 마음체크인

참여자는 기본 정보와 개인정보·상담 연락 동의 여부를 입력한 뒤 CES-D 및 PSS-10 문항에 응답합니다. 결과 화면은 점수를 진단명으로 단정하지 않고 자기돌봄을 위한 안내로 해석하며, 응답 흐름에 따라 말랑이 추천과 지원 메시지를 제공합니다. 만족도 문항은 한국어·영어·일본어로 제공되며, 운영자가 설문 문항을 관리할 수 있습니다.

CES-D는 지난 1주를 기준으로 한 20문항 도구이며, 일부 긍정 정서 문항은 역채점됩니다. PSS-10은 최근 한 달의 지각된 스트레스를 살피는 10문항 도구로, 이 프로젝트에서는 두 점수 모두 비진단적 맥락에서만 사용합니다.[1] [2]

### 운영자용 대시보드

운영자 화면은 소유자 확인과 별도 관리자 비밀번호 확인을 거쳐 접근하도록 구성되어 있습니다. 운영자는 학과별 응답 현황을 확인하고, 상담 연락에 동의한 참여자 목록을 분리해 검토할 수 있습니다. 또한 상담 신청 링크를 관리하고, 점수·원문 응답·주관식 만족도 응답을 포함한 원자료를 실제 Excel(`.xlsx`) 파일로 내보낼 수 있습니다.

| 기능 | 설명 |
| --- | --- |
| 응답 수집 | 기본 정보, 동의 여부, CES-D·PSS-10·만족도 응답을 검증하여 저장합니다. |
| 다국어 UX | 설문·안내·만족도 문항을 한국어·영어·일본어로 제공합니다. |
| 운영 통계 | 학과 필터를 적용한 집계와 응답 목록을 제공합니다. |
| 상담 연계 | 상담 연락 동의자를 별도 목록으로 확인하고, 상담 신청 URL을 설정할 수 있습니다. |
| 원자료 관리 | 운영 권한을 확인한 뒤 UTF-8 한글을 포함한 XLSX 파일로 내보냅니다. |

## 아키텍처와 디렉터리

프런트엔드는 React와 Vite로, 서버 API는 Express 위의 tRPC로 구성했습니다. Drizzle ORM이 MySQL 또는 TiDB 데이터베이스와 연결되며, 로그인 세션은 OAuth와 서명된 쿠키를 사용합니다. 서버와 클라이언트는 TypeScript 타입을 공유해 설문 입력과 운영 API의 계약을 일관되게 유지합니다.

```text
client/                 React 사용자 화면 및 관리자 대시보드
  src/pages/            설문, 결과, 운영자 화면
  src/components/       재사용 UI 컴포넌트
server/                 Express, tRPC 라우터 및 비즈니스 로직
  routers/              설문·만족도·운영자 API
  _core/                인증, 세션, Vite 개발 서버 연동
drizzle/                스키마와 데이터베이스 마이그레이션
shared/                 공통 상수와 타입
```

## 로컬 개발 환경 실행

### 1. 사전 요구 사항

로컬 실행을 위해 **Node.js 22 LTS**, **pnpm 10**, 그리고 MySQL 8 이상 또는 TiDB 데이터베이스를 권장합니다. `pnpm-lock.yaml`을 기준으로 의존성을 설치하므로 npm이나 yarn 대신 pnpm을 사용해 주세요. Git과 데이터베이스 접속 정보도 필요합니다.

| 도구 | 권장 버전 | 용도 |
| --- | --- | --- |
| Node.js | 22 LTS | TypeScript 서버 및 Vite 빌드 실행 |
| pnpm | 10.x | 고정된 의존성 설치 및 스크립트 실행 |
| MySQL / TiDB | MySQL 8 호환 | 참여자 응답, 설정, 사용자 정보 저장 |
| Git | 최신 안정 버전 | 저장소 복제 및 변경 이력 관리 |

### 2. 저장소 복제 및 의존성 설치

아래 명령으로 저장소를 복제한 뒤 의존성을 설치합니다. Corepack을 사용하면 `package.json`에 지정된 pnpm 버전을 일관되게 사용할 수 있습니다.

```bash
git clone https://github.com/seo100522-svg/2026-2-mind-check.git
cd 2026-2-mind-check

corepack enable
pnpm install
```

### 3. 환경 변수 설정

프로젝트 루트에 `.env` 파일을 만들고, 실제 비밀 값은 각자 보관합니다. `.env` 파일은 Git에서 제외되어 있으며, 저장소에 비밀 값이나 데이터베이스 비밀번호를 커밋해서는 안 됩니다.

```dotenv
# 데이터베이스: 마이그레이션과 설문 응답 저장에 필요합니다.
DATABASE_URL="mysql://USER:PASSWORD@HOST:3306/DATABASE_NAME"

# 세션 서명용: 충분히 긴 무작위 문자열을 사용합니다.
JWT_SECRET="replace-with-a-long-random-secret"

# 운영자 기능: 프로젝트 소유자 식별자와 별도 관리자 비밀번호입니다.
OWNER_OPEN_ID="your-owner-open-id"
ADMIN_ACCESS_PASSWORD="replace-with-a-strong-password"

# Manus OAuth를 사용하는 경우의 애플리케이션 설정입니다.
VITE_APP_ID="your-app-id"
OAUTH_SERVER_URL="https://your-oauth-server.example"

# Manus 내장 스토리지·API 기능을 사용할 때 플랫폼에서 주입하는 값입니다.
BUILT_IN_FORGE_API_URL="https://your-forge-api.example"
BUILT_IN_FORGE_API_KEY="replace-with-a-forge-api-key"
```

`DATABASE_URL`은 데이터베이스 마이그레이션과 실제 설문 저장에 필요합니다. `JWT_SECRET`은 세션 서명에 사용하므로 유출되면 안 됩니다. OAuth 값이 없으면 서버는 시작할 수 있지만, 운영자 로그인과 소유자 권한 확인을 포함한 전체 인증 흐름은 정상 동작하지 않습니다. Manus 환경에서는 해당 OAuth 및 플랫폼 값이 프로젝트 설정을 통해 주입될 수 있습니다.

### 4. 데이터베이스 마이그레이션

빈 데이터베이스를 만든 뒤 아래 명령을 실행합니다. 이 스크립트는 현재 `drizzle/schema.ts`를 기반으로 마이그레이션을 생성하고 적용합니다. 운영 데이터베이스에서는 생성되는 SQL을 검토한 후 적용해야 합니다.

```bash
pnpm db:push
```

### 5. 개발 서버 시작

개발 서버는 Vite 미들웨어를 포함한 Express 서버로 실행됩니다. 기본적으로 `http://localhost:3000`을 사용하며, 해당 포트가 사용 중이면 3000부터 3019 사이의 다음 사용 가능한 포트를 선택합니다.

```bash
pnpm dev
```

브라우저에서 터미널에 표시된 주소를 엽니다. 공용 설문을 확인하려면 홈 화면에서 시작하고, 운영 기능을 확인하려면 유효한 OAuth 로그인, 소유자 권한 및 관리자 비밀번호가 모두 필요합니다.

## 품질 검증과 프로덕션 실행

변경 사항을 올리기 전에는 테스트, 타입 검사, 프로덕션 빌드를 순서대로 실행하는 것을 권장합니다. 현재 프로젝트에는 설문 점수 계산, 관리자 접근 제어, 원자료 XLSX 생성, 언어별 콘텐츠 및 대시보드 요약을 검증하는 테스트가 포함되어 있습니다.

```bash
# 전체 단위·통합 테스트
pnpm test

# TypeScript 타입 검사
pnpm run check

# 프런트엔드와 Express 서버의 프로덕션 번들 생성
pnpm run build

# 빌드 이후 로컬 프로덕션 서버 실행
pnpm start
```

프로덕션 환경에서는 `NODE_ENV=production`과 앞서 설명한 환경 변수를 모두 설정해야 합니다. 운영자 화면에서 다루는 응답 데이터에는 개인정보와 민감할 수 있는 자기보고 정보가 포함될 수 있으므로, HTTPS 적용, 최소 권한 부여, 접근 기록 관리, 내보낸 파일의 보관 기간 및 접근 통제를 별도로 수립해야 합니다.

## 운영 시 유의 사항

이 프로젝트는 학생 지원 프로그램의 **시연 및 비상업적 목적**을 전제로 합니다. CES-D 문항을 온라인으로 배포·복제·변형하려는 경우에는 저작권 및 이용 조건을 별도로 확인해야 합니다. 또한 점수 결과만으로 정신건강 상태를 진단하거나 위기 여부를 판정해서는 안 되며, 위기 상황에서는 전문기관과 긴급 지원 체계로 연결해야 합니다.[1] [3]
